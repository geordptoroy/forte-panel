# O7.5 — Dead-letter para falhas permanentes do webhook

## Objetivo

Evitar que uma resposta HTTP 4xx permanente do Panel mantenha um evento Baileys em retry infinito, preservando o envelope para diagnóstico e sem apagar o evento original silenciosamente.

## Entrega

A `WebhookOutbox` agora classifica respostas HTTP 4xx como permanentes, exceto `408 Request Timeout` e `429 Too Many Requests`, que continuam retryáveis. Falhas permanentes são movidas para `outbox/dead-letter/` com o envelope, `lastError`, `attempts`, `quarantinedAt` e `quarantineReason`.

Respostas 5xx, timeouts e erros de rede continuam seguindo o backoff e o limite de tentativas existentes. Envelopes inválidos continuam sendo separados por quarentena local. A outbox não remove dados de forma destrutiva e o diretório de dead-letter não é reprocessado como fila ativa.

## Validação

`npm exec vitest run src/webhook-outbox.test.ts` passou com 3 testes. `npm run check` e `npm run build` do gateway passaram. `pnpm check` do Panel e `git diff --check` também passaram.

## Limitações honestas

A fatia foi validada localmente com dependências fixadas e o patch Baileys aplicado. Não houve alteração na sessão real, no Docker do usuário ou em eventos de produção. O `CORE_ONLY_MODE` continua ativo. As vulnerabilidades reportadas pelo `npm ci` são do conjunto de dependências existente e não foram alteradas com `npm audit fix --force`.
