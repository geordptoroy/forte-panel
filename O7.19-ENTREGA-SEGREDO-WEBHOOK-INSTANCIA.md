# O7.19 — Segredo de webhook por instância

**Data:** 2026-09-30  
**Estado:** concluída em código no Panel e no gateway; validação PostgreSQL/WhatsApp real permanece pendente.

## Implementado

- O Panel resolve `encryptedWebhookSecret` da instância Baileys antes de validar a assinatura.
- Quando existe segredo rotacionado para a instância, o segredo global e o `WEBHOOK_SIGNING_SECRET` não são aceitos para aquele payload.
- Uma assinatura inválida para instância com segredo ativo retorna `401`; a API key não funciona como bypass nesse caminho.
- Foi criado `rotateBaileysWebhookSecret(workspaceId, instanceId)`, que gera 32 bytes aleatórios em base64url e grava apenas o valor criptografado.
- A resolução é limitada à instância ativa e ao provider Baileys.

## Rotação no gateway

O gateway agora possui o endpoint interno autenticado `PATCH /api/instances/:instanceId/webhook-secret`. Ele atualiza o segredo do outbox em memória e nunca inclui o segredo no status retornado. A mutação do Panel persiste o valor criptografado, atualiza o gateway e restaura o valor anterior — ou remove o segredo — quando a atualização do gateway falha.

A operação não reinicia a sessão Baileys; ainda exige validação externa com duas entregas reais.
