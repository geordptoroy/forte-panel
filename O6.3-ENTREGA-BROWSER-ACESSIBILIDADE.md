# O6.3 — Browser desktop/mobile e acessibilidade

## Objetivo
Criar uma prova regressiva das jornadas críticas que não dependa de liberar rotas beta: conexão WhatsApp, consumo, login e Console Admin continuam sob `CORE_ONLY_MODE`, com navegação operável por teclado e semântica compreensível por leitor de tela.

## Entrega

A suíte `client/src/browser-accessibility.contract.test.ts` verifica:

- `CORE_ONLY_MODE` permanece ativo;
- `/whatsapp-connection` é a jornada core permitida;
- `/plans-usage` e `/dashboard` permanecem bloqueadas no modo core;
- rotas bloqueadas retornam para `CORE_ROUTE`;
- navegação principal e do Console Admin possuem landmarks com `aria-label`;
- controles de menu e navegação do Console usam `type="button"`;
- a jornada WhatsApp expõe `alert`, `status`, `dialog`, `alertdialog`, `progressbar` e labels do número de telefone;
- CSS mantém `:focus-visible`, media queries e overflow horizontal seguro para tabelas/controles móveis.

Também normalizei os botões de navegação do Console Admin para `type="button"`, evitando submits acidentais quando a navegação estiver dentro de um formulário.

## Limite da evidência

Esta fatia cria contratos automatizados no código e não declara smoke browser real, Lighthouse/axe ou operação com usuário autenticado. A prova visual desktop/mobile em staging permanece gate separado, pois este Sandbox não tem uma sessão real de cliente nem deve usar credenciais reais. `CORE_ONLY_MODE` permanece ativo.

## Validação

15 testes frontend focados passaram; `pnpm check`, `pnpm build` e `git diff --check` passaram. O build mantém o aviso conhecido de chunk frontend acima de 500 kB. O CI PostgreSQL da O6.2 passou no run `36736764694`.
