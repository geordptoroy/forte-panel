# O5.3 — Health de gateway, filas, storage e providers

## Objetivo
Dar ao Console Admin uma leitura operacional segura, agregada e acionável do sistema, sem transformar segredos de infraestrutura em dados de UI.

## Entrega

A nova query administrativa `platform.health` retorna um snapshot com `checkedAt`, estado geral e componentes independentes:

| Componente | Sinais utilizados | Dados que não são expostos |
|---|---|---|
| Gateway | instâncias ativas, estados conhecidos e erros de saúde presentes | API key, webhook secret e conteúdo do erro |
| Worker | heartbeat, intervalo, idade do sinal e erro booleano | texto do erro bruto |
| Filas | mensagens outbound `queued`, webhooks recebidos e domain events pendentes/em processamento | payloads e conteúdo de eventos |
| Storage | presença da configuração Forge e flag de mídia privada | URL, chave ou credencial |
| Providers | conexões ativas `validated`, `error` e `pending` | chave, URL privada e último erro |

O estado geral usa os estados `healthy`, `degraded`, `stale`, `not_configured` e `unknown`, sem mascarar configuração ausente como saúde.

## Garantias

O snapshot é somente leitura, exige acesso ao Platform Admin e não chama gateway, provider ou storage externo. Ele usa sinais persistidos e configuração booleana, evitando efeitos colaterais durante diagnóstico. O health por workspace existente foi preservado e continua exibindo canal, worker, fila outbound e falhas tenant-scoped.

## Validação

`pnpm check`, `pnpm build` e `git diff --check` passaram. O build mantém o aviso conhecido de chunk frontend acima de 500 kB. O CI PostgreSQL da O5.2 passou no run `36735198506`, incluindo migration, typecheck e suíte completa.
