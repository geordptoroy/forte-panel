# O7.6 — Observabilidade da dead-letter do webhook

## Objetivo

Tornar visível no status operacional do gateway quando existem eventos na dead-letter, sem reprocessar envelopes e sem expor payloads sensíveis.

## Entrega

O snapshot de cada instância agora inclui `webhookOutboxDeadLetter`, a quantidade de arquivos JSON presentes em `WHATSAPP_WEBHOOK_OUTBOX_DIR/dead-letter/`. A contagem é separada de `webhookOutboxPending` e `webhookLastError`, permitindo distinguir fila ativa de falha permanente que exige diagnóstico.

A contagem é atualizada junto com o refresh da outbox. O endpoint não devolve conteúdo de eventos, URLs, secrets ou payloads; apenas a quantidade. O diretório dead-letter continua fora da fila ativa.

## Validação

`npm exec vitest run src/webhook-outbox.test.ts` passou com 3 testes. `npm run check` e `npm run build` do gateway passaram. `pnpm check` do Panel e `git diff --check` também passaram.

## Limitações honestas

A alteração foi validada no Sandbox com dependências fixadas. Não houve acesso ao Docker/staging do usuário, alteração de sessão, limpeza de volumes ou execução de restore. `CORE_ONLY_MODE` permanece ativo.
